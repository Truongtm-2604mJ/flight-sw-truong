# Static analysis findings log

Every flight source (16 files) was analysed in both builds: test, with `FDIR_TEST_BUILD`, and flight. Five layers were run:

| Layer | Tool and settings |
|---|---|
| Compiler, maximum warnings | GCC 13.3: the `WARN_MAX` set in `tests/Makefile`, 31 warning options, plus `-Wunused-macros` |
| Every compiler warning | clang 18.1.3 `-Weverything` |
| Coding standard | cppcheck 2.13.0 `--enable=all --inconclusive` with the MISRA C:2012 addon. Rule numbers only: the rule texts are licensed and not installed |
| Path-sensitive analysis 1 | clang static analyser (scan-build's engine): core, security, unix, deadcode, optin.portability |
| Path-sensitive analysis 2 | GCC 13 `-fanalyzer` |

Commands: `make -C tests warnings` is the CI gate, 0 warnings with `-Werror`. `make -C tests static` runs the five layers, saves each tool's raw output in `raw/`, and matches every finding against `dispositions.yaml`. Any finding without a disposition, or a "fixed" finding that reappears, fails the command, and so fails CI: "fail on new warnings".

## The honest summary

**No tool found a runtime defect** in the flight code. That means no out-of-bounds access, no NULL dereference, no use of uninitialised memory and no integer overflow that a check could reach. The one path-sensitive warning, from GCC `-fanalyzer` in `process_line()`, was traced by hand and is a false positive (SA-23).

The defects found in this session came from elsewhere:

- **NCR-02**, a line dropped without being counted, was found by the **validation campaign**. No analyser can know that a dropped line had to be counted: the code was well-formed, it just did not do what the requirement says.
- The untested defensive branches were found by **MC/DC measurement**.

What static analysis contributed was a set of deviations to make explicit, and four small fixes. Expect more from it on less exercised code.

**What this is not.** It is not a MISRA compliance claim. The cppcheck addon covers a subset of the rules, without rule texts. Some rules are undecidable by any tool and need review. No deviation records were signed off. On a real project each accepted deviation would be a formal deviation permit, approved by product assurance.
